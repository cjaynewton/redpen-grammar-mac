Reviewed at commit `8623ba3` (version 0.12) on branch `claude/redpen-grammar-review-ir0xs1`. Every Swift file under `Sources/` was read, plus `Package.swift`, `build.sh`, `release.sh`, `install.sh` and the README.

**How this was checked.** This review ran on a Linux machine with no Swift toolchain, no macOS, and the review's rules allowed no downloads. Nothing below was compiled or run. Every finding comes from reading the code and tracing it by hand. The fixes on this branch are small and were written carefully, but they have **not been built**. Before merging, run `swift build` and `swift run redpen-test --safety`. The new tests are in `--safety`.

## 1. Bugs, most serious first

### 1.1 A fix can be typed into the document twice. Fixed (`54bc06f`)

`Sources/Redpen/Watcher.swift`, `apply(_:_:in:)`, around line 728 (line 735 before the fix).

**What went wrong.** To apply a fix, Redpen selects the word, writes the fix into the selection through Accessibility, and then reads the field back. Before this fix, if the field did not read *exactly* as expected, Redpen assumed the write had been ignored and pasted the fix with Cmd+V. But "not exactly as expected" also covers writes the app accepted and then changed:
- smart quotes or auto-correct turned `it's` into `it’s`;
- a browser applied the write a moment later, so the immediate read still showed the old text (the code's own `selectionHolds` comment says browsers do this);
- a rich-text editor normalised spacing.

In each of those cases the selection is now a caret just after the inserted fix. The paste then put the fix in a second time, for example `it’sit's`. Deep check's Replace already guarded against this (the old line 867 re-read the field before pasting), but the one-word fix, **Fix all** and **Clean up** did not.

**How to make it happen.** Turn on smart quotes in Pages or TextEdit, type "The brand lost its shelf space", and accept `it's`. Or accept a fix in a Chrome editor that applies the Accessibility write after a delay. (Unconfirmed which apps do this today. The code path was certain.)

**Fix.** The new `RedpenCore/WriteCheck.swift` makes the decision. Redpen pastes only when the field still reads exactly as it did before the write. It first waits up to 0.3 s for an accepted write to show up. If the field changed in any other way, Redpen stops without pasting. It doesn't beep, because the usual cause is the app restyling the fix (smart quotes), so the fix did go in. The paste itself now has a `ready` check: right before Cmd+V, the field, the selection and focus must all be unchanged.

**Test.** `--safety` has six checks on `WriteCheck.outcome`: written, ignored, auto-corrected, doubled, unreadable, and an accent written another way.

### 1.2 A settings file with one typo is replaced by the defaults. Fixed (`8b513ef`)

`Sources/Redpen/Config.swift`, `load()` (line 141); `Sources/Redpen/Settings.swift`, the Reload button (line 534); `SettingsModel.config.didSet` (Settings.swift line 10).

**What went wrong.** The comment says a file that fails to parse is never overwritten, and `load()` does avoid saving it. But the app then runs on the defaults, and every other save path writes those defaults over the file:
- any toggle in Settings;
- the Checking switch;
- **Stop these tips**;
- **Done** in the welcome window;
- the **Reload** button. Reload is the worst case, because a user clicks it right after a hand edit.

The README sends people to edit this file by hand to add banks and apps to skip. Those lists, plus the vague-word lists, the Deep check notes and every style tip setting, were silently lost. The privacy lists did fall back to the built-in ones, so nothing was exposed, but the user's own additions were gone.

**How to make it happen.** In Settings > Advanced, click Open. Add `"com.example.app",` with a trailing comma to `excludedApps`, save, then click Reload.

**Fix.** Before anything can save over an unreadable file, Redpen copies it aside as `config.unreadable-<date>.json`, readable only by your account (`Private.keepUnreadable`). The same broken file is copied only once. Reload now leaves a file it can't parse alone and beeps.

**Still to do.** Show a message saying the file has a typo, instead of only the beep and a log line.

**Test.** `--safety` has five checks on `keepUnreadable`.

### 1.3 Terminal mode can capture a passphrase and show it on screen. Not fixed

`Sources/Redpen/TerminalMode.swift`, `key(code:chars:flags:)` (lines 58–84), `tick()` (line 109) and `fix()` (line 163).

**What goes wrong.** Terminal mode keeps every key typed on the current line in `buffer`. It cannot tell that the shell is showing a `Password:` or `Enter passphrase` prompt: a terminal has no secure text field, and Terminal.app's Secure Keyboard Entry is off by default. Say a passphrase has four or more words, at least three quarters of them plain words, and one word the dictionary flags, such as `correct horse battery stapel`. Then:
- after 0.9 s the bubble pops up showing the words;
- if the user clicks **Fix it**, `Mistakes.shared.record` saves the flagged word and its fix to `mistakes.jsonl`;
- the text is also sent to the local LanguageTool.

It never leaves the Mac, but it appears on screen and lands in a file.

**How to make it happen.** In Terminal, run `sudo -k; sudo true` and type a four-word passphrase with a typo.

**Suggested fix.**
1. Before showing the bubble, read the focused terminal's text through Accessibility; Terminal and iTerm2 expose it. Skip when the last line ends in `password:`, `passphrase`, `PIN:` or `token:`.
2. Skip while `IsSecureEventInputEnabled()` is true.
3. Never record terminal fixes in the mistakes list, or record only the lesson id.

### 1.4 Fix all can paste the wrong word, or the old clipboard, in slow apps. Unconfirmed

`Sources/Redpen/Watcher.swift`, `applyEach` (line 640: an 800 ms pause between pastes) and `Paste.replaceSelection` (line 960: the clipboard is restored 0.6 s after Cmd+V).

**What goes wrong.** Cmd+V is sent and not confirmed. In apps that need the paste fallback (Word, many Electron apps), two timing problems remain:
- If the app reads the clipboard more than 0.6 s after Cmd+V (Word on a large document, or any app that is busy), the writer's own clipboard is already back, and **that** is pasted over the mistake. That could be an image, a password just copied, or a paragraph from elsewhere.
- In Fix all, if the first paste hasn't run when the next fix puts its word on the clipboard 0.8 s later, the first mistake gets the second fix's word.

**How to make it happen.** Open a long Word document while the Mac is busy. Copy some text, then use Fix all (Control-Option-Shift-R) on a paragraph with three spelling mistakes.

**Suggested fix.** After Cmd+V, wait until the field reads `expected` before restoring the clipboard or starting the next fix. Poll the value every 50 ms for up to about 3 s, as `tryStep` already does. If it never shows up, stop Fix all, and don't restore a clipboard the app may still be about to read.

### 1.5 The Keyboard card can freeze typing across the whole Mac while Redpen is busy. Unconfirmed

`Sources/Redpen/Panel.swift`, `installKeys()` (line 672).

**What goes wrong.** With the **One by one, with the keyboard** style, a card that is open installs an active session event tap (`.defaultTap`) on the **main** run loop. Every key press anywhere waits for Redpen's main thread before it reaches any app. The main thread does block at times:
- `selectionHolds` sleeps for up to 1.5 s in Replace;
- `Mistakes.record` waits on a file lock with no time limit;
- `Spelling.check` and `isName` run on long text;
- the watchdog exists because the check loop has stalled before.

If the main thread is busy while the card is open, typing in every app stalls until macOS times the tap out, after about a second per key.

**Suggested fix.** Run the tap on its own thread with its own run loop, decide in the callback from a snapshot of `handles` taken under a lock, and hop to the main thread only to act. Or use a passive tap (`.listenOnly`) plus a local key monitor on the card when it is key.

### 1.6 Spelling work repeated 4 times a second slows long documents. Speed bug

These cause the "slow check" log lines and dropped underlines in long documents. More detail in section 3:
- `Spelling.sentence(around:in:)` (`Spelling.swift` line 194) enumerates **the whole field** sentence by sentence. It runs once for each spelling mistake on **every tick, 4 times a second**, through `Watcher.currentIssues` → `Spelling.applyPick` (Watcher.swift line 330). In a 50-page Word document with 30 typos in view, that is up to about 120 sentence walks of the whole document every second, on the main thread.
- `Spelling.isName` (`Spelling.swift` line 47) runs an `NLTagger` over **the rest of the document** from the word to the end, for each capitalised misspelling at a sentence start, on every quick check.

**Suggested fix.**
- In `sentence(around:)`, enumerate only `ns.paragraphRange(for: r)`. Sentences never cross a paragraph break, and the returned offsets stay the same.
- In `isName`, tag only the sentence: `paragraphRange`, or the next 200 characters.

### 1.7 After a crash, the grammar engine Redpen started keeps running forever. Not fixed

`Sources/Redpen/GrammarEngine.swift`, `launch()` (line 68) and `stop()` (line 109).

**What goes wrong.** The Java LanguageTool server (`-Xmx1g`) is stopped only in `applicationWillTerminate`. If Redpen crashes, is force-quit or is killed by `pkill` in `build.sh`, the server keeps running. The next launch finds a server on port 8081 and uses it, but never records it as its own. After that, even a clean quit leaves a Java process holding up to 1 GB until the user logs out.

**Suggested fix.**
- At launch, if the listener on 8081 is this account's and its executable is under `Application Support/Redpen/engine`, adopt it as `server` so it is stopped on quit.
- Or start Java with a small wrapper that exits when Redpen's process ends, for example by watching a pipe that Redpen holds open.

### 1.8 LanguageTool gives up on long paragraphs and keeps retrying. Unconfirmed

`Sources/RedpenCore/LanguageTool.swift` line 95 (a 4 s timeout); `Sources/Redpen/Watcher.swift`, `runLanguageTool` (line 278).

**What goes wrong.** The LanguageTool slice is every paragraph in view, up to 20,000 characters. On an older Intel Mac, or with `level=picky`, a long slice can take LanguageTool more than 4 s. The request then times out and `ltFailedAt` is set. Three seconds later the same text goes again, and every attempt spawns `lsof` first. The result:
- the grammar underlines never appear for that document;
- the Java server stays near 100% CPU on work Redpen throws away.

**Suggested fix.**
- Check only the paragraph at the cursor, plus a cap of about 4,000 characters.
- Cache results per paragraph, as the Apple model check already does.
- Scale the timeout to the slice's length.
- Back off further (10 s, then 30 s) after repeated timeouts on the same key.

### 1.9 Gemini showed as Connected when the check failed. Fixed (`f790f74`)

`Sources/Redpen/MenuPanel.swift`, `Helpers.gemini()` (line 154).

`run()` returns `""` on a 20 s timeout, on a launch failure, or when nothing is printed, and `""` doesn't contain "sign in". So offline, or with a stalled `agy`, Gemini showed as **Connected**, and on **Automatic** Deep check could choose it. An empty answer now counts as not set up. (Found by the sub-review of the menu code.)

### 1.10 The "Open at login" switch can show the wrong state. Not fixed

`Sources/Redpen/Settings.swift` lines 11–15, 25.

**What goes wrong.** `try?` hides every error from `register()` and `unregister()`, and the switch keeps whatever the user clicked. A `.requiresApproval` status (approval pending in System Settings > Login Items) reads as Off, and turning the switch on then appears to do nothing.

**Suggested fix.**
- After each call, set the switch from `SMAppService.mainApp.status`.
- On `.requiresApproval`, explain why and call `SMAppService.openSystemSettingsLoginItems()`.

### 1.11 Closing the welcome window with the red button didn't count. Fixed (`7f76c5b`)

`Sources/Redpen/Welcome.swift`.

Only the **Done** button set `welcomed` and stopped the window's timer. Closing the window instead had two effects:
- the welcome came back at **every launch**;
- the window's once-a-second timer kept running for the whole session, and each tick starts a LanguageTool status check that can spawn `lsof`.

The window now has a delegate, and closing it does what Done does.

### 1.12 Style tips that garble a sentence when accepted. One fixed (`b3d5765`)

`Sources/RedpenCore/StyleTips.swift`. Found by the sub-review of the tip patterns, and checked against the regexes here:
- **Fixed.** Claims with no source, line 182. "Our experts recommend replacing the filter yearly." offered to cut "experts recommend", leaving "Our replacing the filter yearly." The pattern now skips experts with an owner in front, as the studies pattern on line 181 already did. There is a test in `--safety`.
- **Not fixed.** Softeners, line 168. `I think(?: that)?` eats a "that" that points at a noun: "I think that quote is too high." becomes "Quote is too high." And "What do I think?" becomes "What do?" Suggested fix: take "that" only when a pronoun or article follows it, and skip questions.
- **Not fixed.** Softeners, line 172. "We offer a different kind of warranty." becomes "We offer a different warranty." This changes the meaning.
- **Not fixed.** Verbs turned into nouns, lines 243–247. "We made a payment of $400." becomes "We paid of $400." Add a negative lookahead for `of` and `about`.
- **Not fixed.** Promises, line 321. The bare `is the best` flags "Of the three quotes, the second is the best."
- **Minor.** Line 104: "Basically, iPhones are…" becomes "IPhones are…"

Tips are off by default and never part of Fix all, so the damage is limited to a fix the writer accepts by hand.

### 1.13 Smaller bugs

- **A fix that didn't go in still counted in Your patterns. Fixed (`2a41770`).** `Watcher.apply` recorded the mistake before writing, so refused writes and cancelled pastes inflated the counts.
- **Test connection said "didn't answer within 1 minutes". Fixed (`4606d6c`).** `DeepCheck.swift` line 324 divided 90 s by 60.
- **Holding the Fix all shortcut's modifier keys. Unconfirmed.** Fix all on Control-Option-Shift-R runs at once, while the keys are still held. If the paste fallback is needed, Cmd+V is posted with only the Command flag, but some apps read the live modifier state and treat it as Cmd-Option-Shift-V (Paste and Match Style), or ignore it. Wait for the modifiers to be released (`NSEvent.modifierFlags` empty, up to 1 s) before the first paste.
- **Data races on shared variables.** `Log.last` and `Log.written` (Log.swift line 13) are written from the watchdog's background queue and from the main thread. A Swift `String` written from two threads at once can crash. This is rare: the watchdog only logs after a stall. Wrap `note` in a lock or a serial queue. `Watcher.lastTick` and `ProgressWatch.last` race the same way but hold plain values.
- **`Mistakes.exclusive` waits on `flock(LOCK_EX)` with no time limit** (Mistakes.swift line 56), and it runs on the main thread from `apply`. A second copy of Redpen holding the lock would freeze the app. `WordLog` already uses a non-blocking lock with retries; do the same here.
- **The Deep check text is visible to other accounts with Gemini.** `DeepCheck.swift` line 277 passes the whole text as a command-line argument to `agy`. On a Mac with more than one login, other accounts can read it with `ps -ww`. Claude and Codex get the text on stdin, which is fine. If the Antigravity CLI can read the prompt from stdin or a file, use that.
- **Deep check replies with Windows line endings are never read as revised.** `DeepReplace.revised` and `wellFormed` (DeepReplace.swift lines 46 and 54) split on `\n` and trim only spaces, so a `REVISED\r` heading is never found. Trim `.whitespacesAndNewlines` per line.
- **Test connection can pass on a short error.** In `DeepCheck.test` (line 144), any reply under 40 characters containing "ok", such as "Invalid token", counts as connected. Compare the trimmed reply with "OK" exactly, ignoring case and final punctuation.
- **Straight double quotes used as inch marks hide mistakes.** `Engine.quoteRanges` (Engine.swift line 78) treats `2" pipe and a 3"` as a quotation, so every mistake between two inch marks is skipped.

### 1.14 Grammar fixes that change correct sentences. Three fixed, the rest open

These come from the hand-written rules in `Rules.swift`, `Confused.swift`, `Confusables.swift`, `Advanced.swift` and `Apostrophes.swift`. A sub-review read them in full, and the patterns below were checked here against the regexes.

Why they rank this high: unlike the Apple model's "maybe" underlines, these come out as **sure** grammar fixes. That means:
- they show even in Calm mode;
- **Fix all applies them without asking about each one**;
- a single wrong rule can rewrite a correct sentence across a whole paragraph.

No crash was found in these files. The index arithmetic was traced, and positions that land inside an emoji make `Range(_:in:)` return nil, which every caller treats as "no".

**Fixed on this branch.** Each has tests in `--safety`.

| Commit | Rule | Correct sentence | Was turned into |
|---|---|---|---|
| `3b614a2` | `andMe`, Rules.swift line 78 | Sarah and her team are coming. | Sarah and she team are coming. |
| `b3893bf` | `contractedOwner`, Rules.swift line 147 | We're new customers. / It's old news. | Our new customers. / Its old news. |
| `4747888` | collocations, Rules.swift line 129 | Please reply at your earliest convenience. / Pricing depends in part on volume. / married with two kids | reply to… / depends on part… / married to… |

How each was fixed:
- **`andMe`:** "her" is dropped from the rule, because it is usually an owner there. "Sam and me went" is still caught.
- **`contractedOwner`:** "new", "old", "recent", "first" and "last" are dropped from the list of words that only follow an owner.
- **Collocations:** pairs that are also correct English are removed: reply/replied at, depend(s) in, afraid for, married with, and insist(ed) to.

**Open.** Each of these has a check in `--review`.

1. **`meAnd`, Rules.swift line 77.** "Me and my new manager met today." becomes "My new and I manager met today." The determiner group takes one word, so the adjective is read as the person. Allow up to two words before the noun, or require the tagger to call the next word a verb.
2. **`twoToo`, Rules.swift line 99.** "Can we get two small and one large?" becomes "too small". Drop `and|or` from the look-ahead, or skip when another number follows in the clause.
3. **`entitled`, collocations.** The pattern ignores case, so "a report entitled The Future of Work" becomes "entitled to The Future…". Match lowercase only, or skip when the next word is capitalised.
4. **Confused words, `Confused.swift`:**
   - line 39: "the policies that affect this team" is flagged as "effect";
   - line 45: "Our biggest expense was stationery." is flagged as "stationary";
   - line 35: "in their next meeting" is flagged as "there";
   - line 37: "Let them hear by Friday." is flagged as "here";
   - line 25: "advice on pricing" is flagged as "advise";
   - line 23: "We appreciate your coming in today." is flagged as "you're".

   In each case the words allowed before or after are too broad. The sub-review lists which words to remove.
5. **Compounds, `Confusables.swift` lines 123–144.**
   - "The May payout was late." becomes "May pay out", because the pattern ignores case.
   - "Proceed to checkout" becomes "check out".
   - "Please make your check out to Acme." becomes "your checkout to".
   - "help her log in" becomes "her login".

   Make "May" case-sensitive, drop `to` from the verb cue, and drop `her`/`first` from the noun cue.
6. **Past/passed, `Confusables.swift` lines 150–167.** "Lunch at half past twelve." becomes "half passed twelve" (this goes through the model layer). Skip after half, quarter or a number, and skip before a number.
7. **Subjunctive, `Advanced.swift` lines 12–16 and 53–54.**
   - "If there was a problem, we would have heard." is flagged, as is "If the invoice was paid last week…".
   - "The request that has been pending" becomes "have" (Unconfirmed: depends on the tagger).

   Require the trigger to be tagged as a verb and a subject right after "that". Skip "if … was" when "would have" follows.
8. **Hyphens, `Advanced.swift` lines 70–75.**
   - "In the long term investors will benefit." becomes "long-term investors", which changes the meaning.
   - "Submit one time sheet per week." becomes "one-time sheet".

   Skip after "in the", and drop "one time".
9. **A possessive with the noun left out, `Apostrophes.swift` line 211.** "Our boxes are blue but the supplier's are green." becomes "suppliers", which changes the meaning.
10. **The colon and dash rules can join two lines, `Rules.swift` lines 6–8 and 37.** `\s+` and `\s*` match line breaks:
    - "…the meeting today:\nWe will ship" becomes "today. We will ship" on one line;
    - "Thanks —\nSam" with the comma fix joins the sign-off.

    Use `[ \t]` instead of `\s`.

**Missed mistakes.**
- `Apostrophes.swift` line 57 checks `notPlural` (year, week, month, day) before the plural cue on line 208, so "two year's notice" is never caught, although the code's own comment uses it as the example.
- Several rules accept only a straight apostrophe: `eachHave` (Rules.swift line 79), Confused.swift lines 25 and 33, and Confusables.swift line 123. So "Each of them don’t", "can’t except" and "don’t backup" are missed with the curly apostrophe that Mail, Pages and Word type by default. Use `['’]` everywhere.

**Speed.** `Rules.isVerb`, `nounAt`, `isPlainVerb`, `isPluralNoun`, `lemma` and `Advanced.nounFollows` each build a new `NLTagger` over **the whole text** for every regex match. `contractionAsObject` copies the text up to each match. On a long document that is work that grows with the square of the length, on the main thread, at every pause in typing. Tag once per call, or tag only the sentence around the match.

## 2. Intel and Apple silicon

- **No Intel-only crash path was found.**
  - `AppleModel.isAvailable` returns false on x86_64 at compile time, so the Intel half never calls FoundationModels.
  - The Java runtime for LanguageTool is chosen per architecture at compile time (`GrammarEngine.swift` line 23), and each half of the universal binary gets the right download.
- **Unconfirmed: confirm FoundationModels is weak-linked.** The app supports macOS 14 but imports FoundationModels, which first shipped in macOS 26. It will only launch on 14 and 15 if that framework is weak-linked. The comment in `Panel.swift` line 745 says the app has run on macOS 14.8, so it probably is. Add a release check:
  - `otool -l "Redpen Grammar.app/Contents/MacOS/Redpen" | grep -A2 LC_LOAD_WEAK_DYLIB` should list FoundationModels for **both** architectures (`lipo -thin`);
  - or add `-weak_framework FoundationModels` to the linker settings.
- **Rosetta.** On an Apple-chip Mac whose user ticked "Open using Rosetta", Redpen runs the Intel half: there is no Apple Intelligence, and it downloads the Intel Java, which runs translated and slowly. Log `sysctl.proc_translated` at launch, so this shows up in bug reports.

## 3. Self-update (Sparkle)

- **A build from source updates itself to the release download. Unconfirmed.** `build.sh` puts `SUFeedURL` and `SUPublicEDKey` into every build, including ad-hoc-signed builds from source. Sparkle 2 accepts an update signed with the EdDSA key even when the installed app has no Developer ID. So someone who built Redpen to read the code gets their build swapped for the notarized download at the next update. That build may also have a different `CFBundleIdentifier` (`REDPEN_BUNDLE_ID`), which loses the Accessibility permission. Leave `SUFeedURL` out unless `SIGN_ID` is a Developer ID, or set `SUEnableAutomaticChecks` to false for those builds.
- **About can say "Up to date" when it isn't known** (About.swift line 91). It shows that whenever any check has run, including one that failed offline or found an update the user skipped. Record the result of the last check.
- **Removing Sparkle's XPC services is right for an app that isn't sandboxed.** Signing Sparkle from the inside out is in the right order for notarization.
- **`appcast.xml` lists only the newest version.** That is fine while every version can update straight to the latest. Once a release needs a newer macOS than 14, keep the older item, or users on 14 are offered an update that won't run. `sparkle:minimumSystemVersion` is hard-coded to 14.0 in `release.sh`.

## 4. Speed

Most serious first:

1. **Work done 4 times a second for no reason.** `tick()` redraws every 0.25 s even when nothing changed, and each redraw does all of this:
   - reads the whole field's text over Accessibility;
   - rebuilds the issue list, including `Spelling.sentence` over the whole document for each typo (see 1.6);
   - asks the app for screen positions for up to 80 issues, which is up to 240 cross-process calls, each allowed 0.5 s.

   Cache the issue list until the text, the LanguageTool key or the model cache changes. Ask for positions again only when the text changed, the window moved (`AX.frame` changed) or the visible range scrolled.
2. **One `lsof` process for every LanguageTool request.** `checkIfReady` passes `fresh: true`, so each check spawns `/usr/sbin/lsof`, which takes about 50–300 ms on a busy Mac. This is a deliberate privacy check. Cache a "yes" for a few seconds as long as the PID on the port hasn't changed: `lsof -Fp` gives the PID; check it with `kill(pid, 0)` and `proc_pidpath`.
3. **The paragraph LanguageTool checks is too big** (see 1.8).
4. **The Apple model runs many calls per paragraph.** For each sentence it runs one rewrite, then two judge calls per change it suggests, one paragraph at a time, every time a paragraph changes. On a laptop on battery that adds up. Skip paragraphs that haven't changed since the last pause (this already happens), and skip sentences that LanguageTool found clean whose rewrite came back unchanged before.
5. **Main-thread disk reads.**
   - `MenuPanel.refresh()` reads and decodes the whole mistakes log every time the menu opens and every time it closes (`go(.main)` is called from `close()`).
   - Every character typed into Settings' "Notes for the editor" writes `config.json`.
   - `Log.note` creates an `ISO8601DateFormatter` and opens the log file for every line.

   Move these off the main thread, wait about half a second before saving the notes, and keep one formatter.
6. **Opening Settings > Advanced starts three helper programs.** There is no cache, and they run one after another with a 20 s limit each, so "Checking…" can sit there for a minute. Reuse the 5-minute cache in `PanelModel` and run the three in parallel.

## 5. Privacy

What already works well:
- Password fields and password managers are skipped.
- The bank-page title check uses whole words.
- LanguageTool is trusted only when this account owns the listener, and that is checked before every request.
- The log is owner-only, holds no text, and starts fresh when an older version's log is found.
- Deep check says where the text is going before it goes, and switches off each helper's tools.

Gaps, most serious first:

1. **Terminal passphrases** (1.3).
2. **Every five minutes, opening the menu asks Google's servers whether you're signed in to the Antigravity CLI, if `agy` is installed.** This happens even if you never use Gemini. The code says `agy models` contacts Google. The README says Redpen sends nothing except the update check and Deep check. Check helpers only when Deep check is set to that helper, or to Automatic, or when the Advanced page is opened.
3. **Automatic picks whichever AI is signed in.** Text can go to a company the writer didn't consciously pick. Deep check does say which company before sending, but only as the text is being sent. The first time Automatic resolves to a helper, ask once: "Send to Anthropic / OpenAI / Google?"
4. **Gemini receives the text on the command line,** where other accounts can see it (1.13).
5. **The log is a timeline of which app was in front.** Every 60 s there is an "alive" line naming the front app, plus each click position and app. The README calls the log "app names and counts". Fair, but say "which app you were in, minute by minute" so nobody is surprised. Or drop the app from the "alive" line.
6. **`config.json` is written with the default permissions and only locked afterwards** (Config.swift `save`). For a moment another account can read it if the folder isn't already locked; `lockFolder()` normally locks it at launch. Write to a temporary file created with mode 0600, then rename it (`.atomic`).

## 6. Things a first-time user will trip on

1. **Redpen adds itself as a login item on first launch without asking** (`main.swift` line 179). macOS then shows a "Background item added" notice for an app the user just opened. Ask in the welcome window instead, as a ticked checkbox.
2. **Checking stops silently on any window whose title contains a bank word.** "Food bank volunteers - Google Docs", a doc called "Chase follow-up", or a page that says "TD" or "ANZ" all switch Redpen off with no sign. The status line says "Click into some text…". Make it say "Paused: this page looks like a bank or payment page", with a one-click "Check this page anyway".
3. **"Full grammar" is a 300 MB download plus Java,** and until then only about 8 in 10 of the README's numbers apply. The welcome window mentions it in grey small print. Make it a clear step, with the size and a button.
4. **The Accessibility permission is lost after each source rebuild** with ad-hoc signing (documented in the README). The welcome window should say why it is asking again, not only "Waiting for permission…".
5. **Deep check "isn't set up". Unconfirmed.** From the code, the menu's Deep check action depends on there being a text field (`canDeepCheck`), not on a helper being installed. The first click may open a window that explains how to install a command-line tool. Mark it "Set up" in the menu until a helper reports connected.
6. **Calm mode is on by default,** so house-style rules switched on in Settings don't underline until **Underline** is switched to **Everything**. Style tips are the exception and show anyway. Say this next to the house-style switches.
7. **Fix box styles other than Keyboard can't be used without a mouse.** The card is a non-activating panel that never becomes key, so Tab and VoiceOver can't reach its buttons. Only the "One by one, with the keyboard" style is keyboard-friendly. Say so in Settings, and give the card's buttons accessibility labels.
8. **Underlines differ only by colour.** Spelling and grammar use the same wave shape, red against blue. That is hard to tell apart with red-green colour blindness. A dotted or double line for grammar would help.
9. **VoiceOver.** The fix box style choices don't announce which one is selected (Settings.swift line 443), and the letter badges "C", "G", "Ge" are read aloud (MenuPanel.swift line 440). Most menu and Settings actions use `.buttonStyle(.plain)` and can't be reached with Tab. A word typed into a word list is lost unless Return is pressed (Settings.swift line 610).
